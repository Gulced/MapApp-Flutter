# Project Summary

## Project Name

MapApp Flutter Client

## Repository

MapApp-Flutter

## Project Status

Medium

## Categories

Mobile, Flutter, Maps

## What It Does

A Flutter mapping client associated with the MapApp project, using map rendering, local persistence, and provider-based state.

## Verified Tech Stack

Dart, Flutter, Riverpod, Google Maps, SQLite, Path Provider

## Core Features

- Google Maps-based map UI
- Riverpod state management
- SQLite local persistence
- UI, view-model, provider, model, and service separation

## Architecture

The client separates UI, view-model, provider, model, and service responsibilities. Riverpod coordinates application state.

## Project Structure and Components

- `lib/ui/` — screens and widgets
- `lib/viewmodels/` — presentation logic
- `lib/providers/` — Riverpod providers
- `lib/models/` — data types
- `lib/services/` — storage/integration services

## Database

SQLite stores local users, map points, and map areas through a versioned database helper and upgrade callbacks.

## Mobile / Frontend Components

Flutter UI, view-model, provider, model, and service folders separate map presentation, application state, data types, REST calls, and local persistence.

## External Integrations

- Google Maps Flutter SDK
- MapApp authentication and map APIs

## Technically Interesting Parts

- Google Maps integration
- Riverpod-managed state
- SQLite local persistence

## Engineering Complexity

The main observable engineering complexity comes from google maps integration, riverpod-managed state, sqlite local persistence.
